# 화성에 맞춘 속도 베이스 · 0.4.4

[새 시연 영상 바로 재생](https://hoyadong1.github.io/DriveSoundtrack/musical-speed-journey.mp4). 0.4.3의 독립 발진음은 속도에 따라 연속으로 음높이가 올라갔지만, 배경 화음의 음 사이를 지나며 억지스럽게 들렸다. 이번에는 그 발진음을 제거했다.

Circuit의 베이스 음표는 기존처럼 화성과 음계에서 고른다. 속도는 **그 음의 기본음·한 옥타브 위·두 옥타브 위 성분의 비율**을 바꾼다. 이들은 모두 같은 음이므로 속도 변화가 화성 밖의 새 음을 만들지 않는다. 별도의 낮은 지속음은 현재 화음의 근음을 연주하며, 화음이 바뀌는 마디에서 함께 음을 바꾼다.

```text
s = clamp(완만하게 반영한 속도 / 130, 0, 1)
기본음 계수 = 0.76 - 0.53s
한 옥타브 위 계수 = 0.12 + 0.57s
두 옥타브 위 계수 = 0.03 + 0.14s
```

따라서 정차에서는 둥근 저음이 중심이고, 130 km/h에서는 같은 베이스 음의 한 옥타브 위 성분이 중심이다. 속도에 따른 음표 강도 변화폭도 줄였다. 속도에 따라 음량만 크게 올리는 설계는 사용하지 않는다. 이 버전에서도 0·40·80·130 km/h가 귀로 어느 정도 구분되는지는 청취 평가가 필요하다.

## 실제 앱 출력

디버그 앱의 오디오 샘플 시간에 맞춰 0→40→80→130→0 km/h를 한 번 연주하고, `AudioTrack.write()`에 전달한 PCM을 단일 WAV로 기록했다. [시연 스크립트](../../demo/archive/record-app-speed-pitch-v043.ps1)와 [영상 생성 코드](../../demo/archive/render-musical-speed-v044.py)를 남겼다. 이번 영상의 속도 입력은 **차량 센서가 아닌 앱 내부 디버그 시나리오**다. 영상의 파형과 속도 곡선은 같은 오디오 샘플 시계를 사용한다.

| 구간 | 평균 속도 | 베이스 RMS |
| --- | ---: | ---: |
| 0–5초 | 12.5 km/h | 0.05075 |
| 5–10초 | 48.6 km/h | 0.05132 |
| 10–15초 | 84.7 km/h | 0.05423 |
| 15–20초 | 123.8 km/h | 0.06204 |
| 20–25초 | 75.9 km/h | 0.05650 |
| 25–30초 | 9.8 km/h | 0.05118 |

28.86초 단일 PCM에 속도 기록 160개가 들어 있고 최고속 130 km/h를 지나 정차했다. 시작 1초 이후의 모든 100 ms 구간에 소리가 있었으며, `test/BassSpeedCheck.kt`에서 정속별 음량보다 고역 성분 비중이 더 크게 변하는 것을 확인했다. 실제 차량 재생과 운전자 선호는 아직 검증하지 않았다.
