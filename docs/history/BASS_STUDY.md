# 베이스 속도별 비교 · 0.4.1

이번 단계에서는 Circuit의 베이스만 분리해서 속도별로 비교한다. 다른 악기의 영향을 빼기 위해 디버그 빌드에 베이스 솔로 스위치를 추가했다. 솔로 WAV는 재생 중인 앱이 `AudioTrack.write()`에 전달한 PCM을 기록한 것으로, 같은 합성 엔진의 베이스 신호를 사용한다. 릴리스 빌드에서 솔로 스위치는 활성화할 수 없다.

## 속도의 역할

속도는 베이스를 단순히 빠르게 재생하지 않는다. 0–130 km/h 범위에서 기본음의 존재감, 2·3차 고조파, 음의 지속 시간을 연속적으로 바꾼다. 추진 입력은 별도로 처리한다. 가속 페달값이 들어오면 페달 위치가 베이스의 배음과 강도를 바꾸고, 페달을 읽을 수 없는 현재 Pleos AVD에서는 양의 속도 변화율로 추진감을 추정한다. 정속 주행 비교에서는 변화율이 가라앉은 뒤의 오디오를 사용한다.

Circuit 기준 베이스 식의 핵심은 다음과 같다. `s = clamp(km/h / 130, 0, 1)`, `a = 평활화된 페달 또는 추정 추진감`이다.

```text
파형 = 0.78·sin(φ) + (0.12 + 0.16a + 0.18s)·sin(2φ) + 0.07s·sin(3φ)
감쇠 = exp[-경과시간·(3.4 - 0.8s + 1.3a)]
음량 계수 = 0.68 + 0.32a + 0.45s
```

속도가 높아질수록 음량과 배음이 늘고 음이 조금 길어진다. 페달/추진감은 현재 음색을 순간적으로 더 거칠게 하고 짧게 만든다. 기본음은 기존 화성 진행과 16스텝 베이스 패턴을 따르며, 속도만으로 음정을 무리하게 올리지 않는다. 실제 결과는 마스터 단계의 `tanh` 제한도 받는다.

## 동일 조건 PCM 비교

`test/BassSpeedCheck.kt`는 매 속도에서 모델을 먼저 평형 상태로 만든 뒤 같은 Circuit 프리셋의 베이스 솔로를 약 4초씩 렌더링한다. RMS는 소리 에너지, `edge`는 인접 샘플 변화량의 RMS로 고역 변화에 대한 간단한 지표다. 청감 평가를 대신하는 지표는 아니다.

| 속도 | RMS | edge |
| ---: | ---: | ---: |
| 0 km/h | 0.04061 | 0.00040 |
| 10 km/h | 0.04327 | 0.00042 |
| 20 km/h | 0.04598 | 0.00045 |
| 35 km/h | 0.05011 | 0.00052 |
| 55 km/h | 0.05579 | 0.00059 |
| 80 km/h | 0.06328 | 0.00071 |
| 110 km/h | 0.07284 | 0.00084 |
| 130 km/h | 0.07968 | 0.00085 |

0→130 km/h에서 평균 베이스 에너지는 약 1.96배, `edge`는 약 2.13배다. 130 km/h는 앱의 매핑 상한을 확인하는 시험값이다. 영상은 Pleos Connect v2.1.0의 P 기어에서 Virtual Console로 속도를 강제 주입한 에뮬레이터 시험이다. 실제 차량의 속도 변화나 주행 안전성을 검증한 결과는 아니다.

## 실제 앱 녹화 PCM

영상에 쓰인 WAV는 Pleos에서 앱이 `AudioTrack.write()`로 전달한 베이스 솔로 PCM이다. 각 장면의 첫 3초를 제외해 속도 평활화와 프리셋 전환을 기다린 뒤 `demo/analyze-bass-v041.py`로 측정했다. 장면별 길이와 화성 위치가 달라 위의 동일 조건 수치와 완전히 같을 필요는 없다.

| 속도 | 분석 길이 | RMS | edge |
| ---: | ---: | ---: | ---: |
| 0 km/h | 10.44초 | 0.04285 | 0.00047 |
| 10 km/h | 8.82초 | 0.04580 | 0.00051 |
| 20 km/h | 7.10초 | 0.04822 | 0.00056 |
| 35 km/h | 9.05초 | 0.05242 | 0.00063 |
| 55 km/h | 7.17초 | 0.05887 | 0.00071 |
| 80 km/h | 9.03초 | 0.06579 | 0.00086 |
| 110 km/h | 7.36초 | 0.07693 | 0.00097 |
| 130 km/h | 9.05초 | 0.08372 | 0.00108 |

실제 녹화에서도 8개 단계 모두 RMS와 `edge`가 증가했다. 녹화 스크립트가 일부 파일을 `PcmCapture.close()` 전에 복사하여 WAV 헤더 44바이트가 0인 경우가 있었다. `demo/repair-bass-headers-v041.py`로 **PCM 본문은 바꾸지 않고** 샘플 수에 맞는 WAV 헤더만 복구했으며, 향후 녹화에서는 RIFF 헤더가 완성될 때까지 기다리도록 스크립트를 수정했다. 영상의 오른쪽 파형은 이 PCM으로 생성한 분석 시각화다. 에뮬레이터가 앱 영역을 흰 화면으로 캡처하여 그 부분을 파형으로 대체했다.
